## 工程默认值

以下是落实用户需求所需的实现默认值，不表述为用户逐项指定：

- 默认 12 列、80px 行高、8px 横纵间距；Dock 默认 top、48px。
- 行容量由实际 GridViewport 高度计算；每个 Widget 完整放在同一页。
- 页面按数组索引管理，界面页码从 1 开始；每次只渲染活动页。
- 自动排布采用稳定视觉顺序和矩形 first-fit；相同输入必须得到相同输出。
- 普通模式仍允许页面导航、Dock 方向切换和 Widget 内部交互。
- Drag / Resize 过程中遇到切页或容量变化，取消整个事务后再切换 / 适配；连续跨页拖拽不列入本版。
- 核心引擎纯 TypeScript，Vitest Node 测试；原生 CSS、Zustand、pnpm。
- TypeScript 初始化候选为 6.0.3，原因是 TypeScript 7 在 Next.js 的 CLI 检查路径仍标注 experimental；实际版本与构建验证在 Task 001 落定。

## 单个 Widget 过大的用户决定

用户在冻结工作中明确选择：“自动缩小 Widget，以适应当前页”。

已纳入设计第 9 节：横纵跨度分别限制于页容量，缩小后重新放置和挤让；声明的 min/max 保留，并计算不超过页容量的有效范围。自动适配结果作为已提交布局保存。只有连一个 Cell 都不能显示的零容量状态才暂停编辑并提示空间不足。

容量优先于声明 min/max、分别裁减跨度以及不自动恢复旧跨度属于实现默认值，目的是保证整块内容始终可完整容纳并避免无限新建页面。

## 2026-10-05：Task 001 界面调整

- 来源：用户要求“主要内容区域的边距，要和卡片之间的边距一致；去掉页脚的文字描述，显示到顶栏上”。
- 调整：主内容区横向留白随 `gapX`、纵向留白随 `gapY`，默认四边均为 8px；网格外框使用不占布局尺寸的内阴影，避免边框额外增加 1px 留白。
- 信息布局：将行列容量、Cell 尺寸、间距和本页块数量移到顶栏，删除页脚及其占用的布局行。窄窗口使用紧凑顶栏排列。
- 影响：网格获得更多可用宽高，行容量继续由 ResizeObserver 的实际测量决定；不改变坐标换算或分页算法。
- 验收：确认四边留白等于横纵卡片间距，页脚消失，顶栏信息随窗口和翻页更新，页面无双向滚动。

## 2026-10-06：Task 002 移动交互边界

- 来源：用户要求“接下来实现块移动、拖拽功能”。
- 调整：进入编辑模式后整块 Widget 可通过 Pointer 事件移动，按整数 Cell 吸附并在当前页边界内夹紧；普通模式只允许选择，不改变布局。
- 当前阶段：保留开始前快照，移动只更新临时预览，Pointer Up 一次提交，Pointer Cancel / Escape 取消；选择状态显示编辑轮廓。碰撞挤让、跨页和连锁处理保留给 Task 003。

## 2026-10-06：Task 002 拖拽反馈与删除边界

- 来源：用户要求拖拽时显示跟随效果，碰撞时禁止移动并提示“被遮挡”，编辑模式下禁止选中块内容并提供删除按钮。
- 调整：活动 Widget 使用临时 preview 坐标渲染；目标矩形与同页其他 Widget 相交时保持最近合法坐标、标记 blocked 并显示“被遮挡，无法放置”，Pointer Up 不提交非法位置。
- 调整：编辑模式为 Widget 及其内容设置 `user-select: none`；每个 Widget 左上角显示警告色 `−` 按钮，仅编辑模式可删除，删除事件不启动拖拽。
- 影响：删除只修改当前活动页的布局并保留其他 Widget id；不引入挤让、交换或撤销功能，继续遵守 Task 003 以前的碰撞边界。

## 2026-10-06：Task 002 落点预览框

- 来源：用户要求“移动时，要能看到落地前的预览框”。
- 调整：拖拽中的 Widget 继续跟随临时坐标，同时在同一落点显示不拦截指针事件的虚线预览框；合法落点使用绿色，遮挡状态使用警告色。

## 2026-10-07：Task 003 算法基础

- 调整：新增纯 TypeScript 的 `reflowDraggedItem`，按固定页容量执行 AABB 碰撞检测、稳定行优先 first-fit、向后挤让和失败回滚。
- 边界：本次先交付可测试的布局解析函数；实际视口行容量接入拖拽事务后再启用跨页提交，避免用无限高度替代固定页面。

## 2026-10-05：主内容容器去除卡片外观

- 来源：用户要求“去掉主要内容的卡片背景和边框”。
- 调整：移除 GridViewport 的背景、作为边框的内阴影及圆角，网格直接显示在页面底色上。
- 验收：容器背景透明、无边框和阴影；保持现有 8px 留白、顶栏信息和分页布局。

## 2026-10-08：Task 003 碰撞跨页与 Task 004 Resize 接入

- 来源：用户要求“继续往下实现”，按冻结设计与开发计划继续完成碰撞挤让、跨页和 Resize。
- 调整：拖拽或 Resize 的临时布局通过统一的 AABB first-fit 解析；当前页无法安置的受影响 Widget 自动创建后续页，无法生成合法布局时完整回滚。
- 调整：编辑模式选中 Widget 后显示右侧、底部和右下角 Resize 手柄；Resize 保留左上角锚点，按整数 Cell delta、页边界和 min/max 约束生成预览，Pointer Up 一次提交，取消恢复事务前布局。
- 影响：Widget id 保持不变，页面仍为固定有限容量且无滚动；不引入锁定、Undo / Redo 或独立 Swap 策略。
- 验收：纯引擎和 Zustand 事务测试覆盖跨页挤让、越界回滚、尺寸约束、碰撞补位与提交；Chrome 验证确认编辑选中后出现三个 Resize 手柄并可改变跨度。

## 2026-10-08：Task 006 排布预制功能

- 来源：用户要求“下一项”，按冻结设计第 7、8、10 节实现 Task 006。
- 实现默认值：本页补位保持 x/w/h 和所属页，以视觉顺序寻找更靠上的合法 y；不移动其他页面。全部自动排布复用已有 `compactLayout`，按 page/y/x/id 的稳定顺序从第一页进行矩形 first-fit，清理末尾空页。
- 交互：两个图标放在网格辅助线按钮后，仅在编辑模式显示；零容量或 Drag / Resize 事务期间禁用。提交排布后清除选中项，并将活动页限制在新页数内。
- 验收：[Task 006 验证报告](./task006-validation.md) 记录算法、Store、生产构建及真实 Chrome 结果。
